# Claude Desktop Profiles 使用说明

Claude Desktop Profiles 使用 Go + NSGo 管理 macOS 上 Claude Desktop 的账号目录。主窗口是 480 pt 宽的单列账号列表，右上角依次是在线刷新、添加账号、关于和设置；设置页里可以进入会话管理页。

## 账号与在线数据

- 当前账号排在最前，带蓝色描边和绿色在线点。每张卡片第一行是邮箱，第二行是套餐徽章和「Stripe · 11月16日续费」这样的订阅信息；App Store 等接口不返回续费日时只显示渠道。
- 套餐徽章：FREE 描边、PRO 紫色、MAX 琥珀橙（原 Max 5×）、ULTRA 石墨金（原 Max 20×）、TEAM、ENTERPRISE；未知套餐以灰色原样显示名称。
- 额度按行显示：5 小时、每周，以及 Fable 等每个模型额度各占一行；70% 起变橙、90% 起变红。重置权益以小标签显示，标明类型（「完全重置」或「Fable 重置」等）和到期时间，3 天内到期的标为橙色；悬停某个标签只显示这一条权益的剩余次数、到期时间和作用。
- 卡片底部一行是「当前使用 · 订阅有效 · 注册于 X · 已活 N 天」，右侧是单账号在线刷新、在访达中显示配置文件夹和归档（当前账号不能归档）。
- 当前账号的主按钮是「打开 Claude」，其他账号是「切换」，待登录账号是「登录」。切换、添加、归档、同步、清空日志、清除缓存都会先弹确认框。
- 接管、新增、切换、归档仍操作本地账号目录。
- 切换、添加账号和「立即同步」都要退出再重新打开 Claude Desktop。确认后会弹出进度面板，逐步显示：退出 Claude Desktop（等待它保存数据，可能需要十几秒）、同步 Code 会话（开启共享时）、切换账号数据、重新打开 Claude Desktop。完成后显示结果并自动收起；失败时面板保留，标出失败的步骤和原因。
- 添加账号：确认后 Claude Desktop 退出并以全新环境打开，列表顶部出现「新账号 · 等待登录」卡片并列出步骤；每 5 秒检查一次，登录完成后自动识别并提示「已添加新账号」。登录的账号已在列表里时卡片会提示重复，请在 Claude Desktop 里退出后换一个账号登录。等待期间可点「放弃添加，切回 …」回到原账号并归档空的新环境（重复账号状态下不提供）。
- 公开账号资料来自 `GET https://api.anthropic.com/api/oauth/profile`，额度与重置权益来自 `GET https://api.anthropic.com/api/oauth/usage?cedar_ember=1`。使用对应账号已有的 OAuth 凭证，不授权、不续期、不修改服务端数据。
- 资料接口的 `full_name`、`display_name`、`billing_type`、`subscription_status`、`subscription_created_at` 和账号创建时间会写入本应用的展示缓存。卡片底部显示「注册于 YYYY-MM-DD · 已活 N 天」，取自账号的 `created_at`；未返回的日期不显示。悬停提示只展示接口返回的资料，不展示本地采样时间、查询时间或缓存时间。
- `subscription_created_at` 是订阅创建时间，不代表当前计费周期，界面不显示。只有接口实际返回到期或下次扣款时间才显示「到期」或「续费」；资料接口目前不返回这两个字段，因此暂不显示。
- 重置权益只显示接口返回的 `resets_left` 和 `ends_at`，不按过期或暂停状态推算次数，不提供使用或提交重置的操作。接口的 `type` 对两种权益都是 `full`，类型按 `clears` 判断：清掉 `seven_day`（整个每周额度）的是完全重置，否则是模型重置，模型名取自同一响应里的模型额度名。缺少权益数据时显示「未查询」；接口明确返回空列表时显示「暂无」。
- 从凭证键发现组织并核对在线账号与组织身份，不再依赖 Desktop 的 IndexedDB、HTTP 响应缓存或本地用量历史取得业务数据。多个组织无法唯一确定时停止，避免选错账号范围。
- 右上角「在线刷新」按顺序查询全部已登录账号：卡片依次显示「等待刷新」「正在查询额度…」「✓ 刚刚更新」或「刷新失败 · 原因，下面是上次的数据」，标题栏显示「刷新中 2/4」，结束后显示「已更新 3 · 失败 1」或「已停止 · 更新 2/4」。刷新进行中再次点击按钮即停止。单账号刷新图标只查询该账号。菜单栏的「在线刷新额度」与右上角按钮相同。
- 展示接口观测到的真实用量及重置时间，不把经过重置时间的旧值推算为 0%。缺失的额度用「—」占位，未返回的模型额度、权益和日期不补造数据。
- 失败保留上次成功数据并显示错误，未知额度与实际 0% 分开显示。

## 缓存与请求频率

本应用在 `~/Library/Application Support/Claude Profiles/online-cache.json` 保存在线返回的公开展示数据、采样时间、上次请求和冷却状态，不保存 OAuth 令牌。设置位于同目录的 `settings.json`。

- 默认手动刷新。应用启动、开发热重载、切换页面和窗口激活均不主动查询账号接口，即使缓存已经过期。
- 设置页「额度刷新」可选择 1、5（默认）、15、60 分钟的自动刷新有效期。只有明确开启自动刷新后，才会更新已过期账号；缓存尚有效时重启仍不会重查。
- 手动刷新可以更新尚未过期的数据，但同一账号至少等待 1 分钟。所有账号顺序查询，避免并发请求放大。
- 冷却期间刷新按钮禁用，悬停可查看剩余时间和下次可刷新时间；批量刷新跳过冷却或正在查询的账号，不计为失败。
- 查询失败会在账号和顶部提示中显示具体原因；后续查询成功或恢复到更新的成功数据后，旧错误会自动清除。
- 请求前先持久保存冷却时间；另一进程或开发重启不能绕过冷却。失败采用 1、2、4、8 分钟等指数退避，上限 64 分钟，并遵循更长的服务端 `Retry-After`。
- 设置页「其他 › 清除显示缓存」会移除资料及额度，不会清除请求冷却记录。清除后默认等待用户手动在线刷新。
- 缓存按档案和账号隔离；读取时验证本地登录身份。请求期间账号、配置或目录发生变化时丢弃结果。

## 代理与在线请求

账号查询沿用 Desktop 当前代理配置，支持已实现的固定代理、PAC 和系统代理路径。显式配置无法解析时停止，不静默回退直连。

资料与额度请求统一携带对应账号的 `Authorization: Bearer …`、`anthropic-beta: oauth-2025-04-20`、`anthropic-version: 2023-06-01`、`Accept: application/json`，以及本应用版本、macOS 版本和设备信息请求头。权益查询使用 Claude Code 客户端请求标识，优先静态读取本机安装版本，未安装时使用参考协议版本 `2.1.321`；不启动 CLI、不读取 CLI 凭证。

每个账号接口请求前，向 `https://api.anthropic.com/cdn-cgi/trace` 发送不带凭证的出口查询；仅在出口地区符合内置支持名单时读取凭证，并在同一条已核验 TLS 连接上请求该接口。连接变化即停止。地区名单依据 [Anthropic Supported Regions Policy](https://www.anthropic.com/legal/supported-regions) 维护；该检查只报告已观测的出口地区。

## 钥匙串授权

应用通过 macOS Security.framework 读取「Claude Safe Storage」。首次查询需要在系统授权窗口输入登录钥匙串密码，并选择「始终允许」，让系统记住对 Claude Desktop Profiles 的授权。

开发模式和默认打包均使用 `nsgo.yaml` 中的 `sign.identity`，默认是本机 `Apple Development` 开发证书。`go tool nsgo dev` 每次重编译后会先完成同一身份的签名，再重新启动应用；`make dev` 和 `make run` 使用相同身份。签名失败会显示构建错误，不会回退到临时签名。

首次选择「始终允许」后，后续构建应继续使用同一证书和应用标识。更换签名证书、应用标识或重置钥匙串访问控制后，macOS 仍可能要求重新确认。

钥匙串访问由 macOS 的条目访问控制决定，构建配置不会自动授权读取 Claude 的条目；应用不修改该条目的访问控制，也不保存登录钥匙串密码。

## 出口 IP

点击底栏右侧的出口信息，或设置页「出口 IP › 重新查询」后，沿用 Claude Desktop 当前生效的代理，向 `https://api.anthropic.com/cdn-cgi/trace` 查询出口 IP。再通过 `https://ipwho.is/{IP}` 获取国家、地区、城市、ASN 和 ISP；两个请求均不使用账号凭证。

底栏显示「国家代码 · IP」，悬停可查看城市与地区、ISP 和 ASN，失败时附上原因。

- 启动只恢复 `exit-info.json` 中的上次结果；切换页面不会触发查询。
- 两次出口查询至少间隔 1 分钟，失败采用指数退避；trace 限流时遵循服务端 `Retry-After`。
- 同一 IP 的 GEO 结果保存 24 小时；IP 变化后重新查询 GEO。GEO 失败至少等待 15 分钟，限流时遵循更长的 `Retry-After`。
- 出口查询失败保留上次结果；GEO 服务失败仍显示本次 trace 的 IP，并标注 GEO 暂未更新。

## HTTP RAW 日志

在线账号请求使用 req Transport 和 Chrome TLS 模板，日志保存在 `~/Library/Logs/Claude Profiles/HTTP/`：

- `request.raw`：实际 HTTP/1.1 请求行、请求头及正文。
- `response.raw`：原始响应状态、头部及正文，保留分块格式。
- `metadata.json`：trace/profile/usage 类型、时间、耗时、代理、状态与完整性信息。

RAW 日志按产品约定不脱敏，包括认证头。目录 `0700`、文件 `0600`，保留最近 100 次交换、总量 20 MiB，不输出到终端。

设置页「请求日志」显示目录、请求次数、占用空间和最新一次的时间，可在访达中打开目录，或确认后清空全部记录。

## 窗口与本地会话

默认窗口 480 × 760，宽度可在 480–600 之间调整，高度在 560–1100 之间；不支持全屏和缩放。浅色 / 深色跟随系统。关闭按钮隐藏窗口，应用只驻留在菜单栏：Dock 图标和 ⌘Tab 切换器里的条目一起隐藏。从菜单栏图标打开主窗口或任一页面，或在访达、启动台里再次打开应用，窗口和 Dock 图标都会回来。

菜单栏图标的菜单分三组：

- 账号：当前账号排在最前并打勾，每行附 5 小时和每周用量；选中其他账号会打开主窗口并弹出切换确认，下面是「添加账号…」。还没有账号时显示「接管当前登录…」。
- 常用操作：打开 Claude Desktop、在线刷新额度（刷新中变为「停止在线刷新」）、Code 会话共享开关（规则同底栏开关）。
- 窗口：显示主窗口、会话管理…、设置…、关于…，最后是退出。

有操作进行时，菜单顶部显示当前状态，账号和需要确认的操作暂时不可选。

本地 Code 会话共享继续使用已有 transcript，不覆盖账号凭据或项目 memory。组织身份来自已经核验的在线资料缓存；首次共享前请先完成在线刷新。底栏和设置页的开关控制共享，「立即同步」确认后会退出 Claude Desktop，把其他账号的会话合并到当前账号，再自动重新打开。关闭共享不会重启；关掉后没切换过账号就重新打开时，直接恢复、不重启；关掉期间切换或添加过账号，重新打开会走「立即同步」并先确认。详见[本地 Code 会话共享](workspace-sharing.md)。

### 会话管理

从底栏「会话共享 ›」或设置页「会话管理」进入。页面只读取，不会改动任何会话文件，也不会退出 Claude Desktop。

- 顶部可按标题或工作目录搜索；摘要卡显示会话数、账号数、上次同步结果（新增、更新、跳过），跳过时可展开原因。
- 「全部 / 未全部同步 / 有问题」筛选；会话按天分组，每行显示标题、工作目录、最近活动时间和账号头像，灰色头像表示该账号还没有这个会话。
- 有问题的会话会注明原因，例如对话记录缺失、工作目录已不存在、工作目录由 Claude 临时管理。
- 每行的「···」菜单只提供「在访达中显示工作目录」和「复制会话 ID」。删除会话请在 Claude Desktop 里操作，删除会自动同步到其他账号。

## 关于与在线更新

右上角的「关于」按钮打开关于页：应用图标、版本、简介，「检查更新」，以及 GitHub 仓库、版本说明和问题反馈三个链接。应用菜单里也有「关于 Claude Desktop Profiles」和「检查更新…」。

在线更新使用 NSGo 集成的 Sparkle：

- 打包版每天自动检查一次 GitHub 上 gopkg-dev/claude-desktop-profiles 最新 Release 里的 `appcast-macos_arm64.xml`；有新版时 Sparkle 弹窗说明，确认后下载、校验 EdDSA 签名、安装，并重新打开本应用。是否自动检查可在 Sparkle 的弹窗里更改。
- `go tool nsgo dev` 和测试是开发版本，不检查更新，关于页的按钮显示为不可用。

## 开发与验证

在项目根目录运行 `go tool nsgo dev`。开发重启遵循同一套持久缓存及冷却规则。

启动构建产物时显式添加 `--refresh-once`，会在账号目录读取完成后在线刷新一次，操作与「在线刷新」按钮相同。此参数不写入设置，也不会绕过账号冷却；省略时维持普通启动行为。

```sh
make test
make vet
make test-native
make build
```

测试使用模拟账号和 HTTP 数据。真实账号查询通过应用中的在线刷新操作触发。产物在 `dist/`，安装包在 `dist/releases/`。
